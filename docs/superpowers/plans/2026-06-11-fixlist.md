# Consolidated Fix List — verified findings (2026-06-11)

Sources: Fable's range review of `345cee6..HEAD` (multi-agent, verified) and the
triaged survivors of DeepSeek's recursive-subagent roast (most of its top
"CRITICAL" items were already fixed in `ea3edbf` or refuted on runtime semantics —
see conversation; only verified-live items appear here).

Execution: TDD per item where a test is feasible, one commit per item,
`npm run typecheck && npm test` green before every commit. **The suite is
currently RED (3 transcript tests) — item 1 fixes that; nothing else ships
until the suite is green.**

## P0 — broken now

- [ ] **1. Transcripts dead: pass `recordIteration` into the agent config.**
  `src/engine/harness.ts` builds the `recordIteration` closure (~line 54) but the
  `new RlmAgent({...})` config object omits it. Add `recordIteration,` to the
  config. The 3 failing tests in `tests/transcripts.test.ts`/`tests/harness.test.ts`/
  `tests/service.test.ts` are the acceptance criteria — they must pass unmodified.

- [ ] **2. Malformed JSON wipes judge criteria.** `readBody()` resolves `{}` on
  parse failure; `/api/judge` then does `body["criteria"] ?? []` →
  `setJudgeCriteria([])`. Fix at the right depth: make `readBody` resolve
  `null` on parse failure and have every POST handler return 400 on `null`
  body (one guard in `route()`, not per-endpoint patches). Test: POST
  `/api/judge` with body `"lskdjf"` → 400, criteria unchanged.

## P1 — correctness / robustness

- [ ] **3. Budget the LLM-backed sandbox functions.** `search()` and `evaluate()`
  (and the iteration-0 template's evaluate loop) perform unbounded LLM calls while
  `subAgent()` is capped. Add a per-iteration LLM-call budget shared by
  search/evaluate/llm (e.g. 10), enforced in the sandbox hooks; exceeding it
  throws the same survivable error pattern as the subAgent cap. Tests with
  counting fakes.

- [ ] **4. Rename or implement `search()` honestly.** It is an LLM prompt, not web
  search (`src/engine/search.ts` calls `llm()`); its output enters markets as
  "evidence". Either wire a real search API behind it or rename to `recall()` and
  update `SANDBOX_API_DOC` + template so evidence provenance is honest.

- [ ] **5. Codegen call has no timeout.** A hung provider wedges the agent forever
  (`src/engine/agent.ts` — the `await this.cfg.codegen(...)` is unbounded; the
  sandbox timeout only covers execution). Wrap with a configurable timeout
  (default 120s) that burns the iteration with an error-history entry instead of
  hanging the session.

- [ ] **6. Use the structured error field, not string matching.**
  `agent.ts:92` flags errors via `stdout.includes("ERROR")`; the sandbox already
  returns `result.error`. Use it; keep the string check only for agent-printed
  ReferenceError/TypeError text inside stdout if desired.

- [ ] **7. SANDBOX_API_DOC drift.** Document `evaluate()`, `evidence.list()`,
  `ideas.list()`, `ideas.get()` (and the renamed search/recall) in
  `SANDBOX_API_DOC` so agents can use them deliberately after iteration 0.
  The existing doc-coverage test in `tests/codegen.test.ts` should be extended
  to assert every sandbox global is documented.

- [ ] **8. Empty transition block regression.** `public/app.js:147`:
  `if (wasOptimizing && !s.optimize.running) {}` lost its body in the snapshot
  refactor. Restore the GEPA-history refresh (or, since snapshot now carries
  data, render history from the snapshot and delete the dead branch — pick one,
  don't leave the empty block).

- [ ] **9. TUI lifecycle.** `src/tui.ts`: don't `process.exit(1)` on WebSocket
  close (reconnect with backoff like app.js); guard `setRawMode` behind
  `process.stdin.isTTY`; disable raw mode before each `readline.createInterface`
  and restore after close (the raw-mode/readline stdin conflict).
